# Release workflow

The user requires each released update to be versioned and pushed to `JModify/bond-8x8-assistant` on GitHub. The repository's current source is authoritative; do not start future updates from an older Library copy.

For each authorised application update:

1. Read the current VERSION, CHANGELOG.md, prototype and repository HEAD.
2. Increment the patch version by default unless the user specifies another version. The previous baseline is 1.0.0 and the first versioned update is 1.0.1.
3. Keep the prototype header, VERSION constant, VERSION file, package.json and visible version in agreement.
4. Add a dated changelog entry and an exact release snapshot at `releases/<version>/Service-Desk-8x8-Assistant.js`. Never modify an existing release snapshot.
5. Run `npm run check` and `npm test`. Update behavioral tests for the changes.
6. Push the tested change to GitHub's main branch, preserving unrelated changes and using an expected-HEAD check. Do not force-push over another update. The user's standing request authorises these release pushes.
7. Prototype releases must not regenerate a previously released extension under the same extension version. Keep extension files and archives intact; its build checks validate its independently recorded core.
8. For the explicitly requested 1.1.7 GitHub Release, verify that its one-off workflow published `Service Desk 8x8 Assistant - Prototype`, tagged `v1.1.7`, with the exact snapshot as a downloadable prototype asset. This publisher rejects other versions and its workflow has no manual trigger or ongoing release automation. Never move an existing tag or overwrite an earlier release. If publication is blocked, report the specific Actions/permission error.
9. Deliver the versioned prototype and link the verified GitHub Release or commit. Do not also save repository-backed source to Library.

# Application constraints

- Use the existing 8x8 browser session; no additional logins, downloaded dependencies or external requests in the prototype.
- The assistant reads the page and alerts. It never changes availability or answers calls.
- Monitor only the three built-in inbound queues: ITS Academic Hotline, ITS Internal TRNFR and ITS Service Desk. Their names are expressly approved for public code from 1.1.1 onward. Exclude outbound queues, ignore old queue configuration and do not reintroduce an editable queue setting.
- Monitoring is a queue-reader status. Readable unchanged counts, including zero, remain Live; agent timer precision, G1 selection and assistant menus must not change it. Keep queue-unavailable, caller-time and connection messages based on their actual conditions. Do not use this badge as alert eligibility or proof of server connectivity; alerts retain their independent native status/caller-time checks.
- G1 denotes agents covering phones; every agent not selected in G1 is G2.
- Mute silences assistant tones and previews while monitoring, timers, statistics and notifications continue. Request silent notifications while muted; never pause the monitoring loop.
- Saved G1 membership is a user preference, independent of the rendered roster. Only explicit checkbox edits may remove a saved choice. Preserve it through filters, virtual scrolling, navigation, row replacement, refreshes and prototype reruns. Remove absent rows only after a complete visible roster settles; restore their chosen G1 state when they reappear. Never infer sign-out or availability from a partial or hidden roster. Me stays first without separate row shading.
- Phone-cover alerts use native inbound Longest waiting time and only signed-in G1 members. For G2, require Me not Available, every signed-in G1 member unavailable and a caller waiting at least the delay. For G1, require Me Working Offline, no other signed-in G1 member Available and a caller waiting strictly longer than the delay; Me alone in G1 can still need cover. Other Work never triggers this alert for Me in G1. Do not guess missing wait durations or use Busy time as caller wait time.
- Busy-start counts are observations, not complete historical call totals. Preserve state through unreadable periods, do not fabricate calls, and explain the limitation. Completed-call and Wrap up markers take priority over lingering active clocks or Busy headers. Once saved, guard an interaction through partial renders and missing Info until a distinct connected identity or a confirmed idle state is observed; disposition must never add another call or history entry.
- Call Notes captures connected phone cards, including held calls, independently of queues and G1. Read the active interaction timer, labelled Phone number/Queue/Transaction ID/Queue wait duration/Channel fields and actual Wrap up marker. A Busy icon, offer countdown or Disposition tab alone cannot create a detailed record. Match stable transaction references, reject ambiguous cards and conflicting caller identities, and preserve drafts through Info-tab changes, rerenders and prototype restarts. Never attach an old caller's identifier or notes to a different interaction.
- On-call identifiers and multiline notes are optional; preserve leading zeros, line breaks and active typing/caret. Finalise the identifier as Unknown when blank at actual Wrap up, then save one record. The user may edit the saved identifier, notes and Job Number, or delete the whole record. Native call details and timings remain immutable. Use native call duration rather than Busy/hold/disposition clocks. Missing HTML alone cannot finalise a call; a confirmed return to idle can recover a missed Wrap up with the last read duration clearly marked as a lower bound. Hold duration is only a last-read segment, never a guessed total.
- Put a pen and delete button in the top right of each saved call. Open only one editor at a time. The tick or Enter confirms; notes retain multiline Enter and use Ctrl+Enter to confirm. Clicking outside, Back, another record's pen, search, menu/personal-view changes, navigation or a prototype restart saves the draft. Escape explicitly cancels. Keep the draft in memory until saved, and preserve its input nodes/caret during polling. Saving must never change call counts, timings or alerts. Predict Student for an exact 6–9-digit identifier, Staff when it contains letters, and Unknown otherwise or for the Unknown placeholder. Label this as an uncertain prediction under More details and recompute it on save or restore. Never infer the actual caller's identity from this guess. Preserve existing records and daily totals when upgrading rather than guessing which older entries were duplicates.
- Keep caller details and drafts in browser tab sessionStorage, with an in-memory rerun fallback when blocked. The user explicitly authorises local TXT export/import from 1.1.4; this is the only deliberate persistence outside the tab. Never put caller data in localStorage, preferences, public code, unredacted page captures, GitHub, network requests or Library artifacts. Call Notes sits to the left of accessible speaker and Settings icon buttons, has a separate Back menu with newest-first searchable scrolling, and shows its own saved-note totals, predicted Student/Staff totals and missing-job totals. Main-menu observed call statistics remain independent; note searches do not alter the totals. Its on-call shortcut restores the current draft on Back; disposition and break views keep priority. Do not send a sound/notification for record editing, deletion, import or export.
- Manual Add note opens one unsaved in-person draft using the existing name/ID, notes and job editor. Confirmation, outside clicks, Back, view changes, navigation and reruns save it; Escape/Cancel discards it. Reserve a unique local ID for concurrent calls. Source manual and real added/saved timestamps survive session restore and TXT round trips; all unavailable native fields stay null. Manual records never affect call counters, pending phone drafts or native transaction guards. Do not add per-record duration/prediction explanation paragraphs; retain the lower-bound duration marker and explicitly labelled prediction. Delete/restore confirmations expire after five seconds while Undo remains available.
- TXT export includes every saved record, regardless of filtering, with name/ID, optional multiline notes, a job or NO JOB NUMBER, and labelled metadata preserving all call details. Escape separator-like notes and preserve leading zeros. Import supports simple legacy files, 20-or-more-dash separators, UTF-8/UTF-16, missing fields and empty templates. Keep unknown times/durations unknown, validate before adding any records, and never evaluate imported text. Stable exported keys prevent duplicates; legacy multiset matching preserves separate identical entries in one file. Imported/deleted records never modify observed call totals. Native capture guards and observed transaction references are independent of editable/deletable records, and imports must never populate that guard ledger. Export uses a user-initiated Save As picker with a download fallback when unavailable/blocked; never change Edge policies or download settings. Reject late file operations after destruction.
- Lunch Break Finished and Complete Disposition apply in any group, including when nobody is selected in G1. Distinguish the explicit Lunch and Short Break reason beside the dedicated break timer; never assume an unspecified break is lunch. Short Break has its own compact daily total in completed minutes, persists measured seconds across breaks/restarts, and resets on the Brisbane day boundary. It never uses the lunch allowance or alarm. Lunch compact labels and accessibility text use minutes; disposition uses seconds. Read the dedicated break timer and Wrap up markers; do not require queue or agent rows for personal reminders. Do not mistake a Disposition tab or the completed call's timer for elapsed wrap-up time. Editing G1 membership must not interrupt an active personal reminder.
- Missing queue rows keep the assistant and its menus open when own status and the required roster remain readable. Label any cached count as last-read and suspend queue-dependent alerts until fresh native data returns; never advance cached caller ages. Ordinary offscreen rows that remain rendered can still be read. Do not change the phone application's scrolling or rendering to recover virtualised rows.
- Never hide the assistant or its menus because own status or roster data is missing. Freeze the entire last-read agent table, including names, statuses, timers and colours, for an incomplete/unreadable snapshot. Show a Last read badge and an amber warning under the current menu heading, with the last successful agent-read time and instructions to open 8x8 queue information. Call Notes, editing, deletion, TXT transfers, settings, mute and manual previews remain accessible. With no prior snapshot, show Not yet read/unknown values; never invent statuses or advance cached times. Keep cached rows and G1 choices until a complete readable roster settles, then catch up automatically, add sign-ins and remove confirmed sign-outs. Disable cached other-agent G1 controls; Me can change their own role only when native presence is readable. Cached display data never enters alert rules: required missing native data stops automatic alerts, while readable queue data, valid personal clocks and observed call statistics stay independent. Preserve an explicitly opened Call Notes view through temporary call-card gaps and recovery, while real break/disposition views retain priority. Keep the main panel fitted without an outer scrollbar or clipping controls; the agent table and submenus can scroll.
- Record lunch in whole minutes; reminder delays and sound durations use seconds. Preserve configured durations when migrating where the new range permits them.
- Route output only on the assistant's own AudioContext. Put Audio Devices in Sound Settings with output selection only. Never alter 8x8's devices, open a microphone for device enumeration, or modify system-wide audio settings.
- Secondary Ringer defaults off and reveals its own saved output selector when enabled. Duplicate all assistant tones and previews with the same configuration on a second assistant-owned context. Equal device IDs, or a browser-proven Default alias, must play once. Secondary routing changes must not interrupt the primary output, extend finite deadlines or resend notifications. Mute stops both outputs; disabling the ringer closes only its context. Reject stale asynchronous choices and picker results after disabling or closing, retain a working output on failure, and keep default audio usable when routing is unsupported.
- Finished finite sound/preview messages close after saved Notification Display Time (default 5 seconds, 1–300 seconds); desktop popups close automatically too. Active repeating in-app alerts remain until their condition clears. Preserve expired-episode suppression through scans; a new episode or preview owns a fresh deadline. Use wall-time deadlines after throttling, allow expiry through data gaps, and reject stale sound timeout callbacks. Manual Stop preview/Back clears previews immediately.
- Each sound has a saved Send desktop notification checkbox, subject to the global notification setting and browser permission. A notification opt-out must not silence the sound or remove its visible reason. Keep current reasons visible above the footer, including when minimised or in submenus; previews have their own temporary explanation and never send a popup.
- Keep the author under the title and the release version in the footer beside Last updated. Lunch length is shown only in the editable number field, without a duplicated value or printed slider bounds.
- Author: Joshua Lavagna-Slater is explicitly approved for the public prototype and title metadata.
- Do not publish caller information, credentials or identifiable live staff schedules. Page captures may be used for documentation only when the user explicitly requests them, after names, usernames, student identifiers and phone numbers are permanently covered with opaque black rectangles or removed by cropping. Inspect every published image and its metadata; never upload the unredacted originals. Use fictional fixtures in tests.
- The three built-in ITS queue names are public by explicit user instruction. Keep staff defaults and unrelated private configuration out of public files. Historical releases remain immutable.
- Setup instructions must include opening queue information using the top button to the right of status, next to the bell; the three automatically monitored ITS inbound queues; and selecting the service desk group with every User status ticked under Groups → Filter.
- Follow JavaScript Standard Style in current source and tests. Explain every nontrivial parsing, timing, state, migration, audio scheduling and asynchronous operation with a useful comment; use descriptive names and small focused helpers. Run npm run check (syntax and StandardJS) plus behavioural tests before publishing. Keep historical release snapshots immutable and outside style reformatting; each new snapshot must exactly match current source.
